# External integration note

A web search on 2026-09-18 did not surface official Link4Sub API, callback, webhook, or postback documentation. The implementation therefore uses a server-issued, single-use reward attempt token, a server-side minimum dwell-time check, tab-return detection on the client, and daily idempotency keys. This prevents immediate return from crediting coins and prevents duplicate claims, but it is not cryptographic proof that an external ad/offer was completed.

An optional server-only endpoint is now available at `POST /api/link4sub/postback`. It accepts `{ token, signature }`, verifies an HMAC-SHA256 signature using `LINK4SUB_POSTBACK_SECRET`, and then completes the existing attempt atomically. It returns `503` until that secret is configured, so it cannot silently act as fake verification. Enable it only when Link4Sub provides an official signed callback contract.
